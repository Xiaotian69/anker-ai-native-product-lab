# Anker AI Native Product Lab 设计规格

## 项目目标

为“2026 AI先锋未来人才大赛——安克创新命题”构建一个可公开访问的静态产品实验室。网站既展示 Anker Aero 10K 航旅安全移动电源候选概念，也演示 SCOPE AI 双闭环产品定义法如何把公开资料、待验证假设、多角色质疑和版本迭代串成可追溯证据链。

项目是赵子健的独立参赛研究，不代表安克官方。AI 模拟只用于提出和挑战假设，不能替代真实用户研究。

## 设计选择

采用单页纵向叙事站点，而不是多路由网站。评委可沿着“问题—方法—证据—评分—评审—产品—迭代—对比—资料”连续阅读，导航仍可直接跳转各实验模块。该结构部署简单、移动端稳定，并能把所有关键证据保留在一次浏览会话中。

其他候选方案包括多路由研究门户和数据仪表盘。多路由门户的信息层级更深，但评委需要频繁切页；纯仪表盘交互密度高，却会削弱产品概念的叙事。单页实验室更适合当前比赛展示时长和纯静态部署约束。

## 信息架构

1. Hero：提出航旅用电问题，声明独立项目，并引导进入实验室。
2. SCOPE：以五阶段流程解释从证据到迭代的双闭环。
3. Evidence Lab：搜索和筛选本地证据卡，清楚区分公开资料、待验证访谈命题和合成演示。
4. Opportunity Map：通过滑块调整 C/F/S/T/W/A/R，实时计算机会得分并比较五个方向。
5. AI Council：按角色顺序播放本地评审记录，展示分歧、约束和方案响应。
6. Product Concept：用原创 SVG/CSS 产品图和功能注释呈现候选硬件概念。
7. Evolution：把证据 ID、发现的问题、设计决策和版本变化连成时间线。
8. Method Comparison：比较传统经验驱动与 AI 原生决策系统。
9. Resources：链接真实资料、研究文档、CSV 模板、角色提示词和比赛 PDF。

## 视觉系统

视觉以深海军蓝背景、亮蓝行动色、青绿色证据色和暖橙风险色构成。大标题使用几何无衬线字体，正文采用系统中文字体栈，避免加载第三方字体。卡片以细描边、低透明度渐变和充足留白呈现消费电子实验室质感。所有图形使用 HTML、CSS 或 SVG 原创绘制，不使用安克 Logo 或第三方产品图片。

响应式断点以 760px 为主：桌面采用双栏或多栏模块，移动端变为单列；导航可横向滚动；表格在小屏转换为卡片；滑块保持至少 44px 可触区域。颜色并非唯一状态提示，标签同时使用文字和图标。

## 数据模型与真实性

每张证据卡包含 ID、标题、场景、问题、严重度、替代方案、来源、访问日期、置信度、数据类型、标签和简短摘要。`PUBLIC_SOURCE` 只用于可以点击回原始网页的可核查摘要；`INTERVIEW_HYPOTHESIS` 明确标注为“访谈待验证”；`SYNTHETIC_DEMO` 明确标注为“合成演示”。项目不把资料摘要伪装成用户原话，也不声称已完成未实际发生的访谈。

机会评分使用：

`O = C × (0.25F + 0.25S + 0.15T + 0.15W + 0.20A) - R`

各输入统一使用 0–5 分。得分仅用于相对排序，可为负值；界面始终说明它不是市场规模或销量预测。核心评分函数、输入钳制、证据筛选和资源路径函数由 Vitest 覆盖。

## 组件边界与数据流

- `src/data/` 保存静态证据、机会、评审、迭代和对比数据。
- `src/lib/` 保存无 UI 依赖的评分、筛选和资源路径函数。
- `src/components/` 按页面模块拆分，组件只接收必要数据。
- `src/App.tsx` 负责导航顺序和页面组合，不承载业务计算。
- 用户操作只改变浏览器内存状态，不写入远端、不收集个人信息。

证据筛选流程为：本地 JSON → 数据解析 → 搜索/筛选状态 → 纯函数筛选 → 卡片列表。评分流程为：默认机会参数 → 用户滑块 → 输入钳制 → 评分函数 → 条形图和比较排序。AI Council 使用本地剧本按步推进，重置后回到未开始状态。

## 错误处理与降级

所有公开来源使用外部链接并显示访问日期；外部网页失效时不影响主站。PDF 与本地资料链接通过 `import.meta.env.BASE_URL` 生成，确保 GitHub Pages 子路径可用。JavaScript 不可用时，静态标题和项目声明仍在 HTML 中；交互列表为空时显示明确空状态。动画尊重 `prefers-reduced-motion`。

## 测试与验收

- Vitest：评分公式、边界钳制、证据组合筛选、GitHub Pages 资源路径。
- TypeScript/Vite：生产构建必须成功，base 必须为 `/anker-ai-native-product-lab/`。
- 浏览器：验证桌面与移动布局、交互、控制台、站内资源与 PDF 响应。
- 内容：扫描虚构数字、绝对安全表述、API Key 和本地隐私路径。
- 部署：GitHub Actions 构建 `dist` 并部署 Pages；上线后再次检查 HTTP 状态和关键文本。

## 发布策略

当前目录是为该项目准备的空 Git 仓库，因此直接使用 `main` 分支，不另建工作树。目标 GitHub 仓库目前不存在，将创建公开仓库 `Xiaotian69/anker-ai-native-product-lab`。提交按“设计与计划、核心应用、研究资料与发布资产”组织，最终推送 `main` 并由 Actions 部署 GitHub Pages。
